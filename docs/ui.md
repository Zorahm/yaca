# Yaca — UI-спецификация

Статус: v2, сведена с прототипом `Yaca.dc.html`.

Документ описывает поведение и состояния. Значения токенов (§2) взяты из дизайн-системы и являются нормативными: если код разойдётся с ними, права спека.

Отличия v2 от v1 перечислены в разделе 16.

---

## 0. Принципы

**Агент работает на глазах.** Каждое действие видно в ленте в момент выполнения.

**Подтверждение одно.** В «Ручном» правка спрашивает разрешения до записи, и на этом решение закончено: файл ложится в рабочее дерево сразу, второй кнопки внизу нет. Дифф читается в ленте после — чтобы видеть сделанное, а не чтобы разрешить его во второй раз.

**Коммит не создаёт никто, кроме человека.** Правки едут в рабочее дерево, и дальше git — руками.

**Плотность.** Рабочий инструмент на весь день: 13.5 px текст ленты, 11.5 px моноширинный в тулах, высота строки диффа 24 px и 20 px в компактном режиме.

**Интерфейс не врёт про состояние.** Работающий тул пульсирует, завершённый помечен галкой, устаревший контекст помечен, необратимое требует подтверждения.

Сетка окна: `grid-template-rows: 48px 1fr auto auto`. Одна колонка. Лента центрируется с `max-width: 760px`, при более широком окне растут поля, а не строка.

Низ окна — стек полос уведомлений над композером. Каждая полоса высотой 44, появляется по своему условию и убирается крестиком. Ряды `auto`, поэтому появление полосы не дёргает высоту ленты.

Диффы живут внутри раскрытой строки действия. Отдельной постоянной колонки для них нет.

### 1.1 Выдвижная панель

Открывается по требованию и ложится поверх ленты справа: ширина 55% окна (минимум 560 px), фон `--bg-panel`, слева граница `--line`, тень. Закрывается по `Esc`, по клику вне и повторным нажатием той же кнопки.

| Панель | Открывается | Содержимое |
|---|---|---|
| Сессии | `▤` слева в шапке | список сессий проекта, поиск |
| Файл | клик по имени файла в строке действия | полный дифф файла на всю высоту |
| Процессы | `▤` справа в шапке | фоновые команды, вывод выбранной |
| Чекпоинты | `/checkpoints` или клик по строке чекпоинта | список точек, дифф от точки |

Открыта всегда одна. Панель не запоминает состояние между сессиями: она нужна, когда в неё зашли, и мешает, когда осталась висеть.

## 2. Токены

Из дизайн-системы ZorahM: тёплая бумага, плотная типографика, один громкий акцент — киноварь. Значения нормативные.

Остальные разделы писались по прототипу и называют токены его именами: `--bg-inset`, `--text-muted`, `--accent`. Прототип различал двадцать восемь цветов, система — тринадцать; разницы между `--text-agent`, `--text-strong` и `--text-body` не видел никто, а выбирать между ними приходилось при каждом новом элементе. Старые имена в тексте спеки читаются по таблице соответствия ниже.

### Цвет

Тем две: Ночь — по умолчанию, Бумага — светлая. Имена у тем общие, различаются значения: компоненты о теме не знают.

| Токен | Ночь | Бумага | Роль |
|---|---|---|---|
| `--paper` | `#16130f` | `#f4efe6` | фон окна и ленты, раскрытая строка действия |
| `--paper-raised` | `#211d18` | `#fbf8f2` | панели, полосы, композер, сообщение человека, кнопки, раскрытая группа, запрос разрешения |
| `--paper-sunken` | `#0d0b09` | `#e9e1d3` | вставки: путь, команда, вывод; поле ввода, чип контекста, чип клавиши |
| `--line` | `#3a332a` | `#d9cfbf` | границы панелей и групп, разделители |
| `--line-strong` | `#857a6b` | `#8a7f70` | граница полей, кнопок, композера, меню; наведение; скроллбар |
| `--ink` | `#f2ece2` | `#1a1611` | основной текст |
| `--ink-muted` | `#a89d8c` | `#5c5347` | второстепенный текст, мета, номера строк |
| `--vermilion` | `#ff5a3c` | `#ff4d2e` | акцент, только заливкой: главная кнопка, активная метка, точка выполняющегося действия |
| `--vermilion-hover` | `#ff7455` | `#ff3d1b` | наведение на заливку акцента |
| `--on-vermilion` | `#16130f` | `#1a1611` | текст на акценте |
| `--vermilion-ink` | `#ff7a61` | `#b3301a` | акцент цветом текста и рамки: сама киноварь не проходит 4.5:1 |
| `--moss` | `#79b98c` | `#255c3f` | добавления, успех |
| `--rust` | `#d98b73` | `#8a3f2a` | удаления, неудача, отказ |

`--moss` и `--rust` — сверх системы: ей хватает одного акцента, а диффу нужна пара «+/−». Обе глуше киновари, чтобы «Разрешить» и «Не удалось» не звучали одинаково громко. Подложки диффа разводятся из них же через `color-mix`, а не отдельными токенами.

Акцент настраивается во внешнем виде (§10). Правило от этого не зависит: акцентом не кодируется смысл, только фокус внимания. Успех — всегда `--moss`, неудача — всегда `--rust`, даже если акцент совпал с ними по цвету.

**Соответствие имён прототипа.**

| Имя в тексте спеки | Токен |
|---|---|
| `--bg-window`, `--bg-tool-open` | `--paper` |
| `--bg-panel`, `--bg-raised`, `--bg-message`, `--bg-hunk` | `--paper-raised` |
| `--bg-inset`, `--bg-code` | `--paper-sunken` |
| `--line`, `--line-soft`, `--line-card` | `--line` |
| `--line-input`, `--line-strong`, `--line-hover` | `--line-strong` |
| `--text`, `--text-body`, `--text-agent`, `--text-strong` | `--ink` |
| `--text-muted`, `--text-dim`, `--text-faint`, `--text-gutter`, `--text-gutter-2`, `--ctx-text` | `--ink-muted` |
| `--accent` заливкой | `--vermilion` |
| `--accent` текстом или рамкой | `--vermilion-ink` |
| `--accent-hover` | `--vermilion-hover` |
| `--accent-ink` | `--on-vermilion` |
| `--ok`, `--add-*` | `--moss` |
| `--danger`, `--del-*` | `--rust` |

`--accent-ink` прототипа и `--vermilion-ink` системы — не одно и то же: первый — текст на акценте, второй — сам акцент цветом текста. Имена похожи, смысл обратный.

### Движение

```css
@keyframes yacaPulse { 0%,100% { opacity:.35 } 50% { opacity:1 } }
```

2 s для пульса кольца состояния, 1.2 s для точки выполняющегося действия. Больше в интерфейсе анимации нет и не нужно. `prefers-reduced-motion` заменяет пульсацию статичной непрозрачностью 0.7.

### Пропсы прототипа

`accentColor`, `showLineNumbers`, `compact` — в приложении это настройки внешнего вида. `showLineNumbers` меняет ширину жёлоба диффа с 52 px на 14 px, `compact` — высоту строки.

## 3. Верхняя панель

Высота 48, фон `--bg-panel`, снизу граница `--line`. Держит навигацию и опознание сессии, а не состояние работы: состояние живёт внизу, рядом с композером, куда и так смотрят.

Слева: `☰` меню приложения, `▤` сессии, `⌕` поиск по сессии, `←` `→` навигация по истории ленты. Иконки 20 px, цвет `--text-muted`, при наведении `--text`, активная получает рамку `--line-hover` и радиус 7.

По центру-слева: заголовок сессии 13.5 px `--text`, генерируется из первого сообщения, правится по двойному клику. Рядом чип проекта: фон `--bg-inset`, радиус 6, паддинг 2/8, 12 px `--text-muted`.

Справа: `▤` процессы со счётчиком-точкой при активных, `⌥` панель чекпоинтов, `⋮` меню сессии — переименовать, дублировать, экспорт, удалить.

Марки в шапке нет. Квадрат с отражённой `C` живёт на домашнем экране и в иконке приложения; в рабочем окне он занимал бы место, ничего не сообщая.

Проект стоит чипом рядом с заголовком: он относится к делу и виден всё время.

## 4. Лента

Вертикальный поток, `gap: 22px`, отступы `20px 18px 8px`, `overflow-x: hidden`. Автоскролл вниз, пока человек не прокрутил вверх; после этого появляется кнопка возврата со счётчиком новых блоков.

Виртуализация обязательна начиная примерно со ста сообщений.

## 5. Блоки ленты

Каждый блок — колонка с лейблом сверху: моноширинный 10.5 px, uppercase, `letter-spacing: 0.08em`. `Вы` цветом `--text-dim`, `Yaca` цветом `--accent`.

### 5.1 Сообщение человека

Карточка `--bg-message`, граница `--line-input`, радиус 10, паддинг 11/13, текст 13.5/1.55 цветом `--text-body`, `text-wrap: pretty`. Инлайн-код моноширинный 12.5 цветом `--accent`.

Вложения — чипы над текстом. Наведение открывает действия: править и переотправить, копировать, откатиться к состоянию до сообщения. Правка создаёт развилку с переключателем `‹ 2/3 ›`, а не переписывает историю.

### 5.2 Текст агента

Без карточки, прямо на фоне ленты. 13.5/1.6, `--text-agent`. Markdown, инлайн-код как выше, блоки кода оформляются как блок вывода (5.5.1) с кнопкой копирования.

### 5.3 Рассуждение

Свёрнуто в строку `▸ рассуждение · 12 с` моноширинным 11.5 цветом `--text-faint`. Во время стриминга — `рассуждает…` с пульсирующей точкой. Разворот показывает текст курсивом цветом `--text-faint`, без подсветки. Настройки «всегда разворачивать» нет (§16, п. 47).

### 5.4 Группа действий

Ключевой компонент. Все действия подряд собираются в группу. В свёрнутом виде группа — это одна строка в общем потоке ленты, а не карточка.

**Что закрывает группу.** Ответ модели. Рассуждение (§5.3) группу не закрывает: модель, которая думает перед каждым вызовом, иначе рисовала бы лестницу групп по одной строке — шесть «Вызван 1 инструмент» вместо одной шапки-итога. Цена известна и принята: действие дорисовывается в группе выше рассуждения, которое к нему привело, и мысль «прочитаю файл» может стоять в ленте ниже самого чтения. Свёрнутое рассуждение — подсобная строка, и компактность здесь важнее порядка.

```
Теперь пишу рендерер. Начну с чистых помощников.

Создано 7 файлов, изменён 1, выполнено 9 команд  +597 −16          ›

Теперь стили — переношу типографику на токены приложения.

Изменено 6 файлов, выполнено 2 команды  +310 −21                   ›

Прогоняю typecheck и тесты.

Выполнено 23 команды (2 с ошибкой)                                 ›
```

Свёрнутая группа набрана тем же кеглем, что и текст агента, 13.5 px, но цветом `--text-muted`: она читается как реплика в том же ритме, только приглушённая. Ни рамки, ни фона, ни отступов сверх обычного `gap: 22px`. Лента получается разговором, в который вставлены строчки отчёта, а не лестницей карточек.

**Шапка-итог.** Собирается интерфейсом из счётчиков по категориям: созданные файлы, изменённые, удалённые, выполненные команды, вызванные тулы. Категория с нулём не упоминается, числительные склоняются. Ошибки идут скобкой после своей категории: `Выполнено 23 команды (2 с ошибкой)`, скобка цветом `--danger`. Справа суммарные `+597` цветом `--ok` и `−16` цветом `--danger` моноширинным 12.5, затем каретка `›`.

**Раскрытие.** Каретка разворачивает группу в список: контейнер с границей `--line-card`, радиусом 9 и фоном `--bg-panel`, строки разделены `border-top: 1px solid var(--line-soft)`, высота строки 42, паддинг 0/16.

```
Создано 7 файлов, изменён 1, выполнено 9 команд  +597 −16          ⌄
┌───────────────────────────────────────────────────────────────────┐
│ Создан segments.ts  +124 −0                                     › │
│ Не удалось изменить segments.ts                                 › │
│ Сверил точные байты строки схемы                                › │
│ Изменён segments.ts  +4 −2                                      › │
│ Нашёл управляющие символы в файле                               › │
│ Проверил, что управляющих символов не осталось                  › │
└──────────────────────────────── ⌄ ────────────────────────────────┘
```

Подпись строки 13.5 px `--text-agent`, имя файла внутри подписи — весом 600 цветом `--text`. Счётчики моноширинным 12.5. Справа каретка `›`, поворачивается в `⌄` при раскрытии самой строки.

Строка неудачного действия: глагол цветом `--danger`, остальное как обычно. Отдельного фона и рамки нет — красного глагола достаточно, а сплошная красная строка в списке из пятнадцати действий кричит громче, чем стоит.

**Пока группа выполняется**, она раскрыта и показывает последние строки; выполняющаяся получает пульсирующую точку `●` цветом `--accent` и подпись в настоящем времени: `Изменяю segments.ts`. По завершении группы точка исчезает, время становится прошедшим, группа сворачивается в итоговую строку сама. Раскрытая вручную группа не сворачивается.

**Высота раскрытой группы.** Своего скролла у группы нет: раскрытая показывает все свои строки, а скроллится лента. Высоту держит содержимое раскрытой строки — дифф и блок вывода ограничены `--h-action-content` и скроллятся сами (§5.5.1). Скролл внутри скролла даёт две полосы на одну ось и колесо, которое попадает не туда.

#### 5.4.1 Кто пишет подпись

Интерфейс подписывает только то, что знает точно и не может ошибиться. Всё остальное подписывает модель.

| Подписывает интерфейс | Подписывает модель |
|---|---|
| Создание файла | Чтение файла |
| Изменение файла | Поиск и grep |
| Удаление, перемещение | Выполнение команд |
| Неудача любого действия | Диагностика и навигация по коду |
| Применение изменений | Загрузка страниц |
| Откат к чекпоинту | Вызовы MCP-тулов |

Причина простая. `Изменён segments.ts +17 −14` — факт, который интерфейс выводит из результата. `Проверил, что управляющих символов не осталось` — смысл, который знает только модель: из строки `rg -n $'\x01' src/` интерфейс не поймёт, зачем её запускали.

**Как это устроено в ядре.** Каждый тул, который подписывает модель, получает обязательное поле `description` в схеме вызова. Модель заполняет его вместе с аргументами. Тулы, которые подписывает интерфейс, этого поля не имеют вовсе, чтобы модель не тратила на него токены и не пыталась переписать факт.

**Требования к `description`:**

- одна строка, до 60 символов, без точки в конце
- прошедшее время, первое лицо: `Сверил байты`, `Нашёл управляющие символы`, `Разобрал обработку зависимостей prism`
- о том, что сделано или выяснено, а не о том, чем сделано: `Нашёл существующее использование буфера обмена`, а не `Запустил rg clipboard src/`
- без имён внутренних тулов и без флагов команды: они видны в раскрытой строке
- в языке разговора: русская сессия — русские подписи

**Если тул упал**, интерфейс отбрасывает описание модели и подставляет свою форму неудачи. Описание пишется до выполнения, поэтому `Проверил, что управляющих символов не осталось` на упавшей команде было бы враньём.

**Если описания нет** — модель не заполнила поле или это старая сессия, — интерфейс показывает саму команду моноширинным. Выдумывать подпись за модель нельзя.

### 5.5 Формы подписей интерфейса

| Событие | Форма | Счётчики |
|---|---|---|
| Создан файл | `Создан <имя>` | `+124 −0` |
| Изменён файл | `Изменён <имя>` | `+4 −2` |
| Изменено несколько | `Изменено 3 файла` | суммарные |
| Удалён файл | `Удалён <имя>` | — |
| Удалён каталог | `Удалён каталог <имя>` | число файлов |
| Перемещён файл | `Перемещён <имя> → <новое имя>` | — |
| Неудача правки | `Не удалось изменить <имя>` | — |
| Нарушен инвариант | `Правка отклонена · <причина>` | — |
| Отклонено человеком | `Отклонено вами` | — |
| Отменено | `Отменено` | — |
| Применение | `Применено к рабочему дереву` | суммарные |
| Откат | `Откачено к 14:32` | число файлов |

Имена файлов в подписях короткие, полный путь показывается в раскрытой строке. Числительные склоняются.

Шапка-итог строится по тем же категориям: `Создано 7 файлов, изменён 1, выполнено 9 команд`. Категория с нулём не упоминается.

#### 5.5.1 Раскрытая строка

Раскрытие происходит внутри группы, строка растёт вниз, соседние остаются на местах.

Первая строка тела — полный путь или полная команда: 12.5 px `--text-muted`, паддинг 0/16, отступ снизу 10. Затем блок содержимого во всю ширину группы.

Содержимое показывается целиком. Кнопки «показать полностью» нет ни у диффа, ни у вывода: раскрытие, за которым нужен второй клик, — это не раскрытие. Высоту держит потолок `--h-action-content`, дальше блок скроллится сам, и вертикальный скролл в ленте есть только здесь.

**Для файловых действий** — дифф по правилам раздела 6.3, с подсветкой синтаксиса и жёлобом вида `+ 124`: знак и номер в одном жёлобе, знак слева цветом изменения, номер справа цветом `--text-gutter`. Длинный дифф рисуется окном (§12).

**Для команд** — блок вывода: фон `--bg-code`, граница `#191e23`, радиус 7, моноширинный 11.5. ANSI-цвета сохраняются.

**Для чтения и поиска** — содержимое или совпадения с номерами строк, оформление то же.

Раскрытая по умолчанию — только строка выполняющегося действия. Всё остальное человек открывает сам: список из пятнадцати действий читается как список, а не как простыня.

### 5.6 Список задач

Обновляется на месте, новый блок не создаётся. Оформление как у группы действий. Строки: `✓` цветом `--ok` для сделанных, `●` цветом `--accent` с пульсом для текущей, `○` цветом `--text-faint` для будущих. Текст сделанных — `--text-faint` с `line-through`.

### 5.7 Запрос разрешения

Инлайновый блок, не модалка. Граница `--accent`, фон `--bg-raised`, радиус 10, паддинг 16/18.

```
┌────────────────────────────────────────────────────────────────────┐
│ Разрешить Yaca выполнить команду?                                  │
│                                                                    │
│ npm ci                                                             │
│ ┌────────────────────────────────────────────────────────────────┐ │
│ │ npm ci --prefer-offline                                        │ │
│ │ в ~/dev/agentchat-api                                          │ │
│ └────────────────────────────────────────────────────────────────┘ │
│                                                                    │
│ [Отклонить 1 Esc] [Отклонить… 2] [Разрешать всегда 3] [Разрешить 4]│
└────────────────────────────────────────────────────────────────────┘
```

Четыре яруса, всегда в этом порядке:

1. **Вопрос.** Одна строка 15/600, цвет `--text`. Называет действие и цель: `Разрешить Yaca удалить src/legacy/?`
2. **Цель кратко.** 13.5, `--text-muted`. Имя файла, имя команды, домен.
3. **Подробность.** Блок `--bg-inset`, граница `--line-input`, радиус 7, паддинг 12/14, моноширинный 12.5, `--text-strong`. Полный путь, полная строка команды с аргументами, полный URL. Второй строкой цветом `--text-faint` — рабочий каталог. Это то место, где человек замечает `&& rm -rf`, поэтому строка никогда не обрезается: перенос или горизонтальный скролл.
4. **Действия.**

**Ряд действий.** Отклонение слева, разрешения справа, между ними растяжка. Порядок неизменен во всех запросах: рука привыкает к позиции, а не читает подписи заново.

| Кнопка | Позиция | Цифра | Клавиша | Вид |
|---|---|---|---|---|
| Отклонить | слева, крайняя | `1` | `Esc` | фон `--bg-inset`, текст `--text-muted` |
| Отклонить… | слева | `2` | — | фон `--bg-inset`, текст `--text-muted` |
| Разрешать всегда | справа | `3` | `⌃⇧⏎` | фон `--bg-inset`, текст `--text-strong` |
| Разрешить | справа, крайняя | `4` | `⌃⏎` | фон `--accent`, текст `--accent-ink` |

Цифра и клавиши — чипы внутри кнопки: моноширинный 11, фон на два тона светлее кнопки, радиус 4, паддинг 1/5. На основной кнопке чипы инвертированы: фон `--accent-ink` с прозрачностью 15%, текст `--accent-ink`.

Цифры идут по позициям слева направо и работают глобально, пока запрос активен, — нажимать `⌃⏎` не обязательно, достаточно `4`. Композер в это время не перехватывает цифры: он ждёт ответа, а не текста.

**Формулировки по действиям.**

| Действие | Вопрос | Цель | Подробность |
|---|---|---|---|
| Команда | Разрешить Yaca выполнить команду? | первое слово команды | полная строка и рабочий каталог |
| Удаление | Разрешить Yaca удалить файл? | имя файла | полный путь, размер |
| Удаление каталога | Разрешить Yaca удалить каталог? | имя каталога | полный путь, число файлов внутри |
| Перемещение | Разрешить Yaca переместить файл? | имя файла | `старый путь → новый путь` |
| Сеть | Разрешить Yaca загрузить страницу? | домен | полный URL |
| MCP-запись | Разрешить Yaca изменить данные в Asana? | имя тула | аргументы вызова |
| Правка | Разрешить Yaca отредактировать файл? | имя файла | полный путь и `+12 −3` |

Про правку спрашивает только «Ручной» (§8): она ложится в рабочее дерево сразу, и этот вопрос — единственное подтверждение, которое у неё есть (§16, п. 37).

**Разрешать всегда** раскрывает выбор области: этот префикс команды, этот каталог, этот тул целиком. Первой стоит самая узкая — цифра, нажатая не читая, должна выдавать меньше всего. Выбор — тем же рядом из цифр. Правило живёт до конца сессии; в `.yaca/settings.json` попадает только через настройки.

**Отклонить** отказывает сразу, одним нажатием, — ровно как обещают `1` и `Esc` на кнопке.

**Отклонить…** — обдуманный отказ, вторым шагом. Он раскрывает поле причины и под ним выбор, на сколько отказ:

```
[ не удаляй node_modules, просто пересобери      ]  [Только сейчас ⏎]
Отклонять всегда:
  ⌃1  команды, начинающиеся с npm
  ⌃2  все вызовы bash
```

Причина уходит агенту вместе с отказом: без неё агент повторит попытку. Поле необязательно. `⏎` отказывает только в этот раз, `⌃1`, `⌃2`… — навсегда в выбранной области; голые цифры здесь принадлежат полю. `Esc` возвращает к ряду.

**Отклонять всегда** — пара к «Разрешать всегда»: те же области, тот же срок, до конца сессии. Следующие вызовы в этой области отклоняются без вопроса, каждый своей строкой «Отклонено вами», и агент каждый раз получает ту же причину. Ему сказано, что отказ постоянный и что тот же результат другой дорогой — другим тулом, командой — добывать не надо. Ход отказ не останавливает: отказ от одного действия — не повод обрывать ход, в котором есть другая работа.

Пока запрос активен, кольцо состояния пульсирует, окно поднимается, при свёрнутом окне уходит системное уведомление. Таймаута нет.

Несколько запросов подряд не накапливаются стопкой: активен всегда один, остальные ждут в очереди, счётчик в углу блока показывает `2 из 3`.

### 5.8 Чекпоинт

Тонкая строка-разделитель, моноширинный 11, `--text-faint`:

```
── ● 14:32 · перед сообщением ────────────────────── Откатить сюда
```

Откат показывает список затрагиваемых файлов и требует подтверждения. После отката в ленту добавляется строка `Откачено к 14:32 · 3 файла`; сообщения не удаляются, но помечаются как относящиеся к откаченному состоянию.

Снимок делается перед каждым сообщением человека и перед каждой разрешённой командой. Перед сообщением — потому что правки уезжают в дерево по ходу турна, и точка до него откатывает весь ход целиком; это же точка, к которой возвращает `Esc Esc` (§13). Теневой репозиторий покрывает и игнорируемые git файлы: `.env` должен восстанавливаться.

### 5.9 Ошибка инварианта

Не отдельный блок, а строка в группе действий с формой `Правка отклонена · src/app.rs не прочитан в этой сессии`. Глагол цветом `--accent`, не `--danger`: сработавшая защита — не сбой, и человеку делать ничего не нужно.

Раскрытие показывает точный текст, который получила модель. Если следующим действием агент исправился, строка остаётся, но приглушается до `--text-faint`: история важна, внимание — нет.

## 6. Изменения

Правки агента не попадают в рабочее дерево сразу. Они читаются в ленте, а применяются осознанным действием из полосы над композером.

### 6.1 Полосы над композером

Полосы изменений здесь больше нет. Она была вторым подтверждением того же, о чём уже спросили до записи (§0, §16.37): правки уезжают в рабочее дерево сразу, применять нечего.

Что было в ней и куда делось. Сводка `3 файла +597 −16` — в шапку-итог группы действий (§5.4), которая говорит то же самое и стоит рядом с действиями, а не внизу экрана. Проект и ветка — в чип проекта верхней панели (§3). Кнопка «Откатить» — в чекпоинт §5.8: точка снимается перед сообщением и откатывает весь ход, а не набор. Решение по файлу — в запрос разрешения §5.7, который спрашивается один раз и до дела.

Кнопки «Создать PR» здесь нет и не будет: Yaca доводит работу до рабочего дерева, дальше git — руками.

#### 6.1.1 Полосы уведомлений

Над композером становятся полосы-уведомления высотой 44, с общей анатомией: иконка, текст, пояснение приглушённым, кнопка действия, крестик. Фон `--bg-panel`, сверху граница `--line`, паддинг 10/18.

```
⚠ Контекст почти заполнен   сожмётся автоматически   [Сжать]   ✕
```

| Условие | Текст | Кнопка |
|---|---|---|
| Контекст ≥ 80% | Контекст почти заполнен · сожмётся автоматически | Сжать |
| LSP упал | rust-analyzer не отвечает | Перезапустить |
| Файл изменён извне | 2 файла изменились вне Yaca | Показать |
| Обновление приложения | Доступна версия 0.4.2 | Установить |

Одновременно показываются не больше двух полос, остальные ждут. Полоса всегда убирается крестиком.

### 6.2 Состояния файла

| Состояние | Цвет бейджа | Текст |
|---|---|---|
| Изменён | `--text-muted` | `изменён` |
| Новый файл | `--accent` | `новый файл` |
| Перемещён | `--text-muted` | `перемещён` |
| Удалён | `--danger` | `удалён` |

Бейдж: рамка цветом состояния с прозрачностью 40%, uppercase 10.5 моноширинный, радиус 4.

Бейдж говорит, что случилось с файлом, а не что человек про это решил. Состояний «принят» и «отклонён» больше нет: решение принимается один раз, до записи (§16.37), и файл в ленте — уже сделанное.

### 6.3 Отрисовка диффа

Одинакова в раскрытой строке действия и в панели.

Сетка строки: `52px 16px 1fr` с номерами, `14px 16px 1fr` без. Моноширинный 12.5, высота строки 24 (20 в компактном режиме).

- заголовок ханка: фон `--bg-hunk`, границы сверху и снизу `--line-soft`, текст `--text-dim`, номера скрыты
- добавление: фон `--add-bg`, знак `+` и текст `--add-text`
- удаление: фон `--del-bg`, знак `−` и текст `--del-text`
- контекст: без фона, текст `--ctx-text`
- жёлоб: `--text-gutter`, 11.5, вправо, `user-select: none`

`white-space: pre`, горизонтальный скролл на контейнер, а не на строку.

Что нужно добавить сверх прототипа:

- **Подсветка синтаксиса** внутри диффа и блока кода есть: строка разбирается Lezer'ом (§12) синхронно, построчно — тег не пересекает границу строки; грамматика выбирается по расширению файла или ограде ``` и грузится лениво из бандла, до загрузки строка простым текстом. Цвета — из токенов `--syntax-*` в обеих темах, под подложками диффа. Разбор целых файлов в воркере (§12) не отменён.
- **Пословная подсветка** внутри изменённой строки, чуть плотнее фона строки.
- **Принятие по ханку.** Файл целиком груб, когда агент в одном файле сделал нужное и лишнее. Кнопки на заголовке ханка, появляются по наведению, доступны только в панели: в ленте это лишняя плотность.

### 6.4 Панель файла

Открывается кликом по имени файла. Шапка липкая: полный путь, бейдж, счётчики. Кнопок решения в ней нет — оно принято один раз и до записи (§16.37). Ниже дифф на всю высоту с полным контекстом и свёрнутыми промежутками `⋯ 18 строк`; скроллится сам дифф.

Стрелками `⌥←` и `⌥→` листаются файлы, которых касалась сессия, не закрывая панель.

### 6.5 Панель процессов

Список фоновых команд: id, команда моноширинным, состояние, время работы. Выбор показывает вывод: кольцевой буфер на 10 000 строк, кнопка «Остановить».

## 7. Композер

Карточка `--bg-raised`, граница `--line-strong` (`--line-hover` в фокусе), радиус 10, паддинг 10/12/8.

Поле: 2 строки по умолчанию, автовысота до 12, дальше внутренний скролл. 13.5/1.5, прозрачный фон, без рамки. Плейсхолдер `Спросить или поручить Yaca…`.

Нижний ряд слева направо: чип режима, подсказка `@файл`, растяжка, кнопка отправки 28×28 с `↑`.

### 7.1 Нижний ряд

Слева направо: чип режима, `＋` вложения, `⌥` диктовка. Справа: модель, уровень усилия, кольцо состояния.

**Чип режима** — текстом без рамки: `План`, `Ручной`, `Авто`, `Правки`. 12.5 px `--text-muted`, при обходе разрешений `--danger`. Клик открывает меню, см. раздел 8.

Ось одна. Режимы взаимоисключающие, и `План` стоит в том же списке, что три уровня доверия, потому что доверие в нём ничего не решает: записывающих тулов у модели нет вовсе.

- `План` — читающие тулы плюс `todo_write`. Записывающие тулы не отдаются модели вообще: слабая модель проигнорирует запрет в промпте и потратит ход на ошибку. Выход через `exit_plan_mode`, который показывает план и ждёт, пока человек выберет режим. Разрешения в плане спрашиваются по строке `Ручной` — своей у него нет, а `web_fetch` есть.
- `Ручной`, `Авто`, `Правки` — полный набор тулов, разница в разрешениях (раздел 8).

**Модель и усилие** справа: имя модели 12.5 px `--text-strong`, рядом уровень усилия рассуждения. Оба открывают списки.

Список моделей собран из всех провайдеров, и каждая модель приводит своего (§10). Модель, которую локальный сервер сейчас не держит в памяти, помечена `не загружена`: выбор такой обернётся долгой загрузкой или ошибкой. Это сообщает сам сервер — поле `loaded` в его списке моделей, которого нет в форме OpenAI. Пометка — живое состояние, поэтому спрашивается при каждом открытии списка и нигде не хранится. Сервер, который об этом промолчал, до конца запуска больше не спрашивается: у шлюза вроде OpenRouter список в сотни моделей, и поле в нём не появится.

**Кольцо состояния** — единственный индикатор работы в интерфейсе, 16 px:

| Состояние | Вид |
|---|---|
| Простой | тонкое кольцо `--text-gutter` |
| Работает | дуга `--accent`, вращение |
| Ждёт решения | кольцо `--accent`, пульс |
| Ошибка | кольцо `--danger` |

Заполнение кольца показывает занятость контекста. Наведение даёт `24k/200k · $0.31`.

### 7.2 Упоминание файла

`@` открывает автодополнение по проекту: нечёткий поиск, ранжирование по mtime и по тому, открывался ли файл в сессии. Выбранный файл становится чипом над полем.

Приложенный файл регистрируется в реестре прочитанного. Иначе получается глупость: человек сам приложил файл, а агент обязан перечитать его перед правкой.

### 7.3 Слэш-команды

`/` в начале строки: `/compact`, `/clear`, `/checkpoints`, `/cost`, `/model`, `/mcp`, `/init`, `/help`. Пользовательские подхватываются из `.yaca/commands/*.md`.

### 7.4 Во время работы агента

Поле не блокируется. Отправленное сообщение встаёт в очередь и показывается чипом над композером: `в очереди · отменить`. Вливается после текущей группы действий, а не после всего турна. Кнопка отправки превращается в `■` и останавливает агента, то же делает `Esc`.

Черновик запоминается на сессию и переживает перезапуск.

## 8. Разрешения

Режим один и переключается чипом в нижнем ряду композера; активный виден всегда, а не только в открытом меню.

```
Режим
  План                                        ✓ 1
  Читать и планировать, ничего не менять
  Ручной                                        2
  Ничего без спроса
  Авто                                          3
  Всё кроме выполнения команд
  Правки                                        4
  Применять правки, спрашивать остальное
  ────────────────────────────────────────────
  Обход разрешений                     Включить
```

Пояснение стоит второй строкой под названием, приглушённым `--text-muted`.

Порядок от осторожного к доверчивому. `План` первым: он осторожнее `Ручного` — там записывающих тулов нет вовсе, тогда как ручной про них спрашивает. Цифры `1`–`4` работают, пока меню открыто.

Дефолт — **Ручной**. Yaca работает с любыми моделями, включая слабые локальные, поэтому безопасное поведение задаётся по умолчанию, а доверие человек выдаёт сам.

| Класс действий | План | Ручной | Авто | Правки |
|---|---|---|---|---|
| Чтение, поиск, LSP | да | да | да | да |
| Правка файла | тула нет | спросить | да | да |
| Удаление, перемещение | тула нет | спросить | да | спросить |
| Команды | тула нет | спросить | спросить | спросить |
| Сеть, запись через MCP | спросить | спросить | да | спросить |

«Тула нет» в колонке `План` — не запрет, а отсутствие: §7.1 отдаёт модели только читающий набор, и запрещать нечего. Единственная строка, где план решает вопрос о разрешении, — сеть, и он спрашивает.

Разрешённое действие происходит сразу — правка ложится в рабочее дерево, файл удаляется, команда запускается. Второго решения ни у чего из этого нет; чем режимы различаются, так это тем, о чём они спрашивают.

Чтобы «Ручной» не превратился в очередь однообразных вопросов, есть «Разрешать всегда» (§5.7): один ответ «всё в `src/`» закрывает вопрос про каталог на сессию.

Очередь бывает и из отказов: модель, которой отказали, тянется к тому же действию снова — на локальной модели это было девять вопросов за ход про один файл. На это есть «Отклонять всегда» (§5.7): один ответ «ничего в `src/`» закрывает и эти вопросы. Отказ старше разрешения: если «всегда» сказано в обе стороны и области пересеклись, побеждает отказ.

**Префикс команды разрешает команду целиком.** «Разрешать всегда» с областью `echo` пропускает и `echo … > README.md` — запись в файл редиректом, без вопроса о правке. Так и задумано: команда есть команда, и «Ручной» про неё спросил. Сузить область до команд без редиректа можно, но `cp`, `tee` и `python -c` разбором строки не поймать, а частичная защита создала бы впечатление, что правка файлов закрыта, — это хуже честной дыры (§0). Кто не хочет правок в обход файловых тулов, отвечает «Отклонять всегда» или не выдаёт префикс.

**Обход разрешений** — не пятый режим, а флаг поверх текущего. Включение требует подтверждения, флаг не переживает перезапуск приложения и сбрасывается при смене проекта. Чип режима и кольцо состояния становятся `--danger`. Отказов «Отклонять всегда» обход не снимает: он значит «перестань спрашивать», а не «сделай то, от чего я отказался».

**Инварианты не отключаются ничем.** Read-before-edit, свежесть файла, уникальность якоря, границы воркспейса, запрет коммита и пуша без явной команды действуют во всех режимах, включая обход. Разрешения ограничивают человека, инварианты защищают от галлюцинаций модели, и переключателя у них нет.

## 9. Сессии

Панель по кнопке `▤` слева в шапке: список сессий проекта по дням, заголовок из первого сообщения, время, стоимость. Поиск по тексту сообщений и по путям затронутых файлов. Действия: переименовать, дублировать до точки, экспорт в Markdown, удалить.

Смена проекта — кликом по чипу проекта в шапке или `⌘O`. Каждый проект хранит своё в `.yaca/`: настройки, правила разрешений, историю, теневой репозиторий.

### 9.1 Домашний экран

Открывается, когда сессия не начата.

По центру приветствие с маркой: квадрат с отражённой `C` и строка `С чего начнём, ZorahM?` 22 px. Имя берётся у операционной системы: учётных записей у Yaca нет, а спрашивать имя ради одной строки — плохая за неё плата. Не нашлось — приветствие обходится без обращения.

Больше на экране ничего нет. Композер и есть приглашение к действию; карточка статистики и примеры запросов, стоявшие здесь раньше, сняты в v2.4 — см. §16. Кнопка провайдеров — единственное исключение: она нужна до первого сообщения, но самому разговору не принадлежит.

Над композером — чип проекта. Чип: фон `--bg-inset`, радиус 6, иконка и имя 12.5 px. Рядом с ним — кнопка «Настроить провайдера»: до окна настроек (§10) она открывает выдвижную панель провайдеров §1.1 (§16, п. 30).

Чип проекта — кнопка, открывающая выбор папки; это тот же способ сменить проект, что и в §9. Папка одна: ядро проносит один корень через рабочее дерево, чекпоинты и разрешения, и `＋`, который заменяет папку вместо того, чтобы добавить вторую, врал бы иконкой.

Композер тот же, что в сессии, с плейсхолдером `Опишите задачу или задайте вопрос`. Нижний ряд §7.1 работает до сессии: режим, модель и усилие выбираются здесь и уезжают в сессию вместе с первым сообщением. Основа — настройки проекта (§10), выбранное в окне поверх них.

Пока папка не выбрана, поле не принимает текст: отправлять его некуда. То же, пока ни один провайдер не настроен (§10): модели, на которой начать, нет, и над композером сказано, что провайдера надо опросить.

Первое сообщение создаёт сессию и заменяет приветствие лентой. Раньше него сессии нет и на диске: запуск, в котором ничего не спросили, не оставляет в панели §9 пустой строки.

Последний открытый проект помнят настройки уровня приложения — в самом проекте хранить его негде, он нужен раньше, чем проект известен.

## 10. Настройки

Отдельное окно, боковая навигация.

| Раздел | Содержимое |
|---|---|
| Провайдеры | список: имя, форма протокола (`anthropic` или `openai`), базовый URL, свои заголовки, модели; ключ каждого — в системном кейчейне; проверка соединения |
| Модели | дефолтная, для подагентов, для сжатия истории, лимиты |
| Режим | режим по умолчанию, сохранённые правила, сброс |
| Инструменты | включение тулов, таймауты команд, деньлист |
| MCP | серверы, статус, список тулов каждого |
| Языковые серверы | язык → команда, статус, перезапуск |
| Проект | путь к `CLAUDE.md`, исключения теневого репозитория, свои команды |
| Внешний вид | акцент из четырёх, номера строк, компактность, размеры шрифтов |
| Клавиатура | переопределение сочетаний |

Провайдер описывается целиком, а не только адресом: одного базового URL мало, чтобы дотянуться до произвольного шлюза. Форма протокола задаётся явно и не угадывается по адресу — OpenRouter и LiteLLM отдают обе с соседних путей одного хоста, и ошибка вскрылась бы не на первом запросе, а на первом вызове тула. Заголовки протокола перебиваются своими, включая заголовок авторизации; значение с `{key}` получает ключ из кейчейна в момент запроса, так что в файле настроек ключа нет никогда.

**Ключ заранее не требуется.** Нет ключа — заголовок, который его ждёт, не уходит, а запрос уходит. Локальный сервер ключа не спрашивает и отвечает; сервер, которому ключ нужен, отвечает 401 или 403, и блок ошибки §5.10 дописывает к его словам `ключ API для «x» не задан`. Требовать ключи до разговора значило настраивать провайдеров, которыми никто не собирался пользоваться, — форма OpenAI по умолчанию просит `Bearer {key}`, и ключ «был нужен» даже локальному Unsloth.

Модели описываются вместе с провайдером: у чужого — свои идентификаторы, окно контекста и цены, и по ним же считается кольцо §7.1 и деньги.

Активного провайдера нет: модель приводит своего, и выбор модели в §7.1 выбирает заодно и провайдера. Открытый чат держит своего провайдера до конца разговора — выбор модели в нём предлагает только его модели. Модель, которой у провайдера нет, — отказ с объяснением, `у провайдера «x» нет модели «y»`, а не подмена первой моделью: открыть старый чат на другой модели, не сказав об этом, хуже, чем сказать, что модели не стало. Первая модель провайдера берётся, только когда модель не названа вовсе.

**Настроен — значит, ответил.** Провайдер настроен, когда его адрес ответил списком моделей; список, вписанный в код, ответом не считается, поэтому встроенные `anthropic` и `openai` приходят без моделей, а их модели появляются после «Опросить». Новый чат в проекте, который модель не называет, начинается на первой модели первого настроенного провайдера. Ни одного настроенного — разговор не начинается, и домашний экран (§9.1) говорит, что провайдера надо опросить.

Провайдеры — уровень приложения, а не проекта: проект не решает, куда уезжает разговор и ключ. Файл, который не разобрался, останавливает запуск, а не подменяется встроенным Anthropic.

**Промежуточный шаг.** Окно с боковой навигацией — цель, но провайдеры уже редактируются выдвижной панелью §1.1 (§16, п. 30). Она открывается кнопкой «Настроить провайдера» на домашнем экране (§9.1) и строкой в подвале сайдбара и закрывает только раздел «Провайдеры» из таблицы выше: список, описание целиком, модели, ключи. Остальные разделы — внешний вид, клавиатура, MCP, языковые серверы, доверие — ждут окна.

В панели говорят только правду о ключе (§0): поле ключа write-only, значение уезжает в кейчейн под `id` и никогда не возвращается на экран; показывается источник — кейчейн, переменная окружения, «нет» или «не нужен» у провайдера, в чьих заголовках `{key}` не встречается. Провайдер без моделей в выборе §7.1 не появляется: сессии нечем было бы отправить запрос. Встроенный `anthropic` кнопки удаления не имеет — ядро его всё равно откажется удалять.

`CLAUDE.md` — единственный файл инструкций, `AGENTS.md` рядом с ним держится симлинком.

## 11. Состояния и ошибки

| Ситуация | Поведение |
|---|---|
| Нет ответа провайдера | блок ошибки с кодом, «Повторить» и «Сменить модель»; ретраи отдельной строкой |
| Нет ключа | запрос уходит без него; отказ 401 или 403 — блок ошибки со словами провайдера и припиской `ключ API для «x» не задан` (§10). Заранее не предупреждается: локальный сервер ключа не просит |
| Ни один провайдер не настроен | домашний экран не отправляет сообщение и говорит, что провайдера надо опросить (§9.1, §10) |
| Контекст ≥ 80% | полоса уведомления с кнопкой «Сжать» |
| LSP индексирует | подпись у кольца состояния `rust-analyzer 40%`; тулы навигации предупреждают о неполноте |
| LSP упал | полоса уведомления с перезапуском, откат на tree-sitter |
| Файл изменён извне | правка отклоняется инвариантом свежести, агент обязан перечитать (§5.9) |
| Отмена турна | незавершённые тулы получают `отменено`, в ленте строка `Остановлено` |

Формулировки: что произошло и что делать. Без извинений и без «упс». `Не удалось подключиться к api.anthropic.com. Проверьте сеть и ключ в настройках.`

## 12. Производительность

- Текстовые дельты применяются пакетами по кадру, а не по событию.
- Markdown парсится инкрементально, незакрытый блок кода рендерится как код.
- Подсветка синтаксиса в воркере, блоки длиннее 200 строк — по требованию.
- Дифф длиннее 200 строк рендерится окном: в разметке живут только видимые строки плюс запас, сверху и снизу их заменяют распорки. Порог не 2000, как было записано раньше: ядро режет дифф на 2000 строках (`MAX_LINES`), и до такого порога дело не дошло бы никогда. Окно держится на том, что строка, заголовок ханка и свёрнутый промежуток лежат на одной сетке высотой `--diff-line`.
- Цель: 60 fps во время стриминга при сессии в 200 сообщений.

Видимый фокус на всех интерактивных элементах, полная навигация с клавиатуры. Лента — `log` с живыми регионами: скринридер получает блок целиком по завершении, а не посимвольно. Контраст не ниже AA. Состояния различаются иконкой и границей, не только цветом, поскольку акцент настраиваемый.

## 16. Что изменилось и почему

Правки v1 после сверки с прототипом:

1. **Три колонки → одна.** Панель контекста упразднена, счётчики переехали в шапку, статус-строка убрана.
2. **Модель применения изменений переписана.** В v1 правки применялись сразу, безопасность держалась на чекпоинтах и модальных запросах. В прототипе правки стажируются и проходят ревью пофайлово. Это лучше: решение принимается по диффу, а запрос разрешения остаётся только там, где нет обратимости. *(Отменено в v2.9, п. 37.)*
